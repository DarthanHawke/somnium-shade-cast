Somnium Shade Cast — проект для хранения и потокового воспроизведения личной музыкальной коллекции на собственном сервере. Основная цель проекта — плеер, который подбирает музыку из коллекции под настроение на основе персонального «теневого» профиля.

**Статус — первый пререлиз (MVP).** Проект активно разрабатывается. Уже доступен полный путь от загрузки файла до воспроизведения в демо-клиенте для Windows и Linux. Развёртывание пока ручное, а настройки по умолчанию рассчитаны на локальное тестирование. Рекомендации, внешние интеграции и общий доступ к библиотекам входят в планы разработки.

## Что уже работает

- Загрузка отдельных аудиофайлов и папок с подпапками, с отображением статуса загрузки и фоновой обработки.
- Библиотека треков, альбомов и исполнителей с поиском, извлечением встроенных обложек и удалением из коллекции.
- Потоковое воспроизведение оригинального аудио с перемоткой, очередью и случайным порядком. HTTP API также поддерживает скачивание оригинала.
- Сервер на Go, каталог в SQLite, зашифрованное файловое хранилище и фоновая очередь, которая обрабатывает принятые загрузки и очищает неиспользуемые блобы.

## Быстрый старт

1. Для сервера нужны исходники пререлиза, Docker и Docker Compose. Для новой библиотеки в `server/.env` из шаблона `server/.env.example` задаётся `SSC_MASTER_KEY` — 32 случайных байта в стандартном Base64. В инструкции есть команды для PowerShell и Linux. [Документация сервера](server/README.md)
2. Из корня репозитория запускается сервер. Готовность проверяется по `/health`. В PowerShell для проверки используется `curl.exe`.

   ```sh
   docker compose --env-file server/.env up --build --detach --wait
   curl http://127.0.0.1:8080/health
   ```

3. Готовые сборки для Windows x64 (`.zip`) и Linux x64 (`.tar.gz`) будут доступны на странице релизов GitHub в блоке **Assets** под описанием пререлиза. После распаковки и установки зависимостей на Windows запускается `somnium_shade_cast.exe`, а на Linux — `./somnium_shade_cast` из распакованного каталога. Также доступна сборка из исходников. [Релизы на GitHub](https://github.com/DarthanHawke/somnium-shade-cast/releases) · [Документация клиента](client/README.md)
4. В поле подключения указывается URL, по которому сервер доступен с устройства, где запущен клиент. Для локального сервера с настройками по умолчанию подходит уже заполненный адрес `http://127.0.0.1:8080`. Если в `server/.env` изменён `SSC_PUBLISH_PORT`, в URL указывается этот порт. В режиме `dev`, включённом в шаблоне, можно создать тестовый профиль, загрузить треки и воспроизвести их после обработки.

## Как работают загрузка и стриминг

1. **Приём файла.** Сервер принимает файл в ограниченный по размеру буфер в памяти и вычисляет SHA-256. При совпадении хеша используется уже имеющийся блоб. Для нового блоба генерируется отдельный ключ. Последовательные блоки по 128 КиБ шифруются AES-256-GCM и записываются в файловое хранилище. В SQLite сохраняются сведения о блобе и его файловый ключ, зашифрованный мастер-ключом сервера.
2. **Добавление в библиотеку.** После регистрации загрузки `POST /ingest/uploads` возвращает `202 Accepted` и идентификатор для проверки статуса. Фоновая задача читает аудио, извлекает теги и обложку и добавляет трек в каталог и поисковый индекс. Трек становится доступен для воспроизведения после успешной обработки.
3. **Стриминг и перемотка.** Для перемотки плеер запрашивает байтовый диапазон исходного файла через HTTP `Range`. Сервер находит покрывающие его блоки, расшифровывает их и отдаёт запрошенные байты с ответом `206 Partial Content`. Обычный запрос возвращает исходный аудиопоток целиком, без перекодирования.

## Что защищает шифрование

Шифрование блобов рассчитано на случай, когда доступны файлы хранилища или их резервная копия, а мастер-ключ хранится отдельно. В MVP SQLite хранится в открытом виде и содержит метаданные библиотеки. При загрузке, обработке и стриминге сервер работает с расшифрованными данными в оперативной памяти. Администратор хоста с доступом к процессу, его памяти или окружению может получить открытые данные или ключ. Мастер-ключ симметричный и нужен при каждом запуске сервера. Для восстановления библиотеки требуется исходный ключ.

В планах — шифрование SQLite и возможность оставить блобы незашифрованными на доверенном личном сервере. Доступ через SSH рассматривается отдельно от шифрования на диске. Для удалённого хостинга шифрование останется предпочтительным способом хранения.

## Планы

- **Рекомендации по настроению.** «Теневой» профиль будет учитывать теги, историю и паттерны прослушивания, чтобы подбирать треки из личной коллекции.
- **Обогащение библиотеки.** Внешние каталоги будут дополнять сведения о треках, альбомах и исполнителях. В карточке альбома можно будет видеть полный список треков, включая ещё не загруженные, а в карточке исполнителя — дополнять локальную коллекцию сведениями о дискографии.
- **Last.fm.** Скробблинг с возможностью указать собственный прокси, в том числе для доступа из России. Отдельная вкладка будет показывать предстоящие релизы и рекомендации треков с учётом профиля Last.fm.
- **Клиенты и развёртывание.** Поддержка новых платформ, включая Android, и автоматическое развёртывание сервера из клиента по SSH.
- **Совместный доступ.** Добавление пользователей из клиента и приглашения для подключения к серверу. У каждого пользователя будет своя библиотека и доступ к трекам, которыми поделились другие пользователи.
- **Тексты песен.** Просмотр, ручное добавление и редактирование текстов, поиск вариантов во внешних источниках и переключение между ними.
